# Lab 05 — Ethernet LAN Switching

## Overview

In this lab, I used **Cisco Packet Tracer Simulation Mode** to observe how Ethernet switches learn MAC addresses and how ARP and ICMP traffic move across a switched LAN.

The lab started with empty dynamic MAC address tables on the switches and empty ARP tables on the PCs. I generated traffic between PC1 and PC3 and observed what happened before and during the ping.

## What I Did

### 1. Observed the ARP Broadcast

PC1 needed to communicate with PC3 at:

```text
192.168.1.3
```

Because PC1 did not initially know PC3's MAC address, it generated an ARP request.

In Simulation Mode, I inspected the frame and confirmed that the destination MAC address was:

```text
FFFF.FFFF.FFFF
```

![Analyzing PC1 packet showing the broadcast MAC address](<analyzing PC1 packet showing broadcast mac address.png>)

*Inspecting the ARP broadcast generated by PC1.*

The switches flooded the broadcast through the LAN so the device using `192.168.1.3` could respond.

### 2. Verified PC1-to-PC3 Communication

I generated traffic using:

```text
ping 192.168.1.3
```

![PC1 ping to PC3](<PC1 ping to PC3 to verify question 1.png>)

*Verifying communication between PC1 and PC3.*

Simulation Mode showed both **ARP** and **ICMP** traffic.

ARP first resolved PC3's IP address to its MAC address. After that, the ICMP echo request and reply could be sent as unicast traffic.

### 3. Viewed PC1's ARP Table

After the communication, I checked PC1's ARP table using:

```text
arp -a
```

![PC1 ARP table after pinging PC3](<PC1 arp table after ping PC3.png>)

PC1 now had a dynamic mapping between PC3's:

```text
IP address → MAC address
```

This showed me how a host remembers the Layer 2 address associated with another IPv4 address on the local network.

### 4. Viewed SW1's MAC Address Table

I checked SW1's learned MAC addresses using:

```text
show mac address-table
```

![SW1 MAC address table](<show mac table for SW1.png>)

The table showed dynamically learned MAC addresses and the switch interfaces associated with them.

This reinforced that a switch learns from the **source MAC address** of incoming Ethernet frames.

### 5. Cleared Dynamic MAC Addresses

I cleared SW1's dynamically learned entries using:

```text
clear mac address-table dynamic
```

and checked the table again.

![Clearing dynamic MAC addresses on SW1](<clearing dynamic mac address for SW1.png>)

The dynamic entries were removed and would need to be learned again when new traffic crossed the switch.

## Key Concepts

| Concept | What I Observed |
|---|---|
| ARP Request | Sent as an Ethernet broadcast |
| Broadcast MAC | `FFFF.FFFF.FFFF` |
| MAC Learning | Switches learn from source MAC addresses |
| Known Unicast | Forwarded toward the known destination port |
| Unknown Unicast | Flooded when the destination MAC is unknown |
| ARP Table | Maps IP addresses to MAC addresses |
| MAC Address Table | Maps MAC addresses to switch interfaces |
| ICMP | Used for the ping after address resolution |

## Key Commands

```text
ping 192.168.1.3
arp -a

show mac address-table
clear mac address-table dynamic
```

## What I Learned

- ARP is used when a host knows an IPv4 address but still needs the destination MAC address.
- ARP requests use the Ethernet broadcast address `FFFF.FFFF.FFFF`.
- Switches learn MAC addresses from the source address of frames they receive.
- A PC's ARP table maps **IP addresses to MAC addresses**.
- A switch's MAC address table maps **MAC addresses to interfaces**.
- A ping may require ARP to occur before ICMP traffic can be delivered.
- Dynamic MAC address entries can be cleared and relearned as traffic crosses the switch.
